合规与电子签名（e签宝）方案

整理自项目创始人的产品构思与合同合规描述。
目标：把"合同合规"这一大块构想，系统化为可直接对接 e签宝 等合规第三方电子签名 / 存证服务的条款与流程。
适用范围：本方案与 contractTemplate.js 中的《数字遗产托管及内容授权服务协议》一一对应，合同条款已固化上述合规点。

一、合规总基调：只做"保管与交还"

平台的核心定位是"表达与交还"，不是信托、银行、财产托管，也不是宣发。

  • 不碰财产：不接收、不保管、不管理用户的任何资金或金融资产，只就用户主动上传的"表达内容"提供存储与投递。
  • 不是创造、不是宣发：平台只是把寄存者留下的内容，交还给其想要表达的对象，仅此而已。
  • 法律风险很低：与其说是法律风险，更可能是社会接纳度的问题。因内容本身引发的争议，由内容提供方（用户）自行承担，平台不承担连带责任。
  • 主动送达：是平台向目标对象"发东西"，而不是对方来领——从根源规避冒领、诈骗与伦理风险。

二、合同内的合规条款（已写入协议，可直接对接 e签宝）

以下条款均已在 contractTemplate.js 的 CONTRACT_BODY 中固化，签约时生成快照 + SHA-256 哈希存证。

1. 内容审核（人工 + AI，加密防盗）

  • 设立内容安全审核机制，人工审核与人工智能（AI）审核相结合。
  • 托管内容全程加密，并采取措施防止网络黑客攻击与未授权访问。
  • 对极端、暴力、血腥、黄色及违法言论，在合同签署前即与用户约定剔除意向；一旦发现，平台立即宣告对此类内容不具有保管、收纳及后期宣发服务。

2. 安全池 / 敏感池 严格隔离（防污染）

  • 托管内容区分为"安全内容池"与"敏感内容池"，二者设置严格界限。
  • 所有公开、改编、陈列用途，仅可取自安全内容池；敏感内容池受到保护。
  • 平台通过"全体接收（进入待选）→ 选择中 → 成功"的分级后台审核，并积累案例形成漏洞库，持续提升防污染与安全意识。

3. 双保险与知情权

  • 保留双方的知情权与接受 / 拒绝权：用户可决定目标对象"是否知悉、是否接受"其内容；目标对象也可选择接受或拒绝。
  • "限定人物"的强约束，仅适用于用户特别指定要求的极少数情形；未特别指定的，任何人触发后仅可联系平台，绝无权限取得内容本身。
  • 平台动作始终是"理性且温情的判断"，而非机械执行。

4. 多处确认 / 勾选（落实社会责任、规避风险）

  • 在协议关键条款处嵌入多处"建议确认、勾选同意或拒绝"环节（内容审核、授权公开、改编收益、限定人物等）。
  • 用户签署前的勾选，构成本协议不可分割的确认记录。

5. 公益提取比例（写入用户手册）

  • 用户服务手册中载明：平台将按约定额度提取一定比例的服务收益用于公益事业。
  • 比例与用途以手册及用户签署时的勾选确认为准。

6. 5 年更新与到期递增提醒

  • 推荐并提醒用户定期更新内容，默认每 5 年一个周期。
  • 临近到期，提醒频率逐年递增（第一年~第五年逐年通知，第五年起每月、每周通知），避免遗忘与家庭矛盾。
  • 更新不影响已按约定完成的历史投递。

7. 匿名公开与改编授权（收益分配进合同）

  • 用户可独立选择是否授权内容匿名化后用于公益展示 / 公共陈列，默认不授权。
  • 用户可独立选择是否授权内容用于改编意向收集（动漫 / 小说 / 影视等），默认不授权。
  • 若授权改编并产生收益，收益分配（给指定对象 / 捐公益 / 留平台）由用户授权时明确选择并写入协议记录。

8. 用户手册与规范化运营

  • 编制详尽的用户服务手册，明确服务流程、审核标准、公益提取比例、隐私保护措施与操作规范。

9. 实物交付与费用（不涉邮政专营）

  • 电子内容免费 / 基础；实物信件、随身物件交付是合理收费依据。
  • 实物寄递通过具备资质的民营合作方或 EMS 完成，平台不经营须经特许的邮政专营业务。
  • 志愿者公益网络可协助孤寡、特殊困难群体的托管与交付，平台不因此额外收费。

10. 触发机制（主动 + 多方验证）

  • 以用户"存在性退场（离世）"作为终极发令枪；亲友、医生、法医等发现后可联系平台作为替补执行链。
  • 发送前做多方验证，绝不只凭"内容被打开 / 被查看"就触发发送。

三、电子签名路径：MVP 自建 → 规模化 e签宝

阶段一（当前 MVP）：平台自建轻量签名

  • 手写电子签名（Canvas 实时采集）+ 内容 SHA-256 哈希存证。
  • 签约时记录：签署时间、唯一合同编号、内容哈希、签署环境（IP / 终端特征）。
  • 提供公开验真页与可打印凭证，作为轻量级法律背书。
  • 局限：自建哈希存证的司法采信力度弱于持牌第三方，适合试水期。

阶段二（规模化）：接入 e签宝 等合规第三方

e签宝 是持牌的电子签名 / 电子合同 / 司法存证服务平台，可提供：

  • 实名认证（个人 / 企业）、意愿认证；
  • 防篡改签署、时间戳、数字证书；
  • 出证报告、司法链存证、在线仲裁 / 诉讼取证支持。

接入条件（需准备）：

  • 企业 / 个体工商户主体（e签宝 签署需实名商事主体）；
  • 完成 e签宝 开发者入驻、API 对接（实名 → 发起签署 → 签署完成 → 下载已签文件 / 证据链）；
  • 签署费用按套餐 / 用量的计费（试水期可先用 MVP 自建方案）。

迁移方式：本协议已将上述全部合规点固化在条款中，迁移到 e签宝 时，只需把 CONTRACT_BODY 作为"合同模板"推送到 e签宝 发起签署，并用 e签宝 返回的签署文件 / 证据链替换自建哈希存证即可，业务字段（合同编号、收件人、授权选项）保持不变。

四、给落地的提醒（非法律意见）

以上为产品合规姿态的设计整理，具体资质、条款效力以当地通管局 / 市场监管 / 法务意见为准。

经营性收费前必须：个体户 / 公司主体 + 域名 ICP 备案 + 经营性 ICP 许可证（B25）+ 微信 / 支付宝商户号。

若使用 e签宝，务必同步落实《个人信息保护法》《电子签名法》下的告知 — 同意与数据最小化原则。
本方案随产品与法规迭代持续更新。
